# Mainnet Security Blockers

## Current blocker

The production branch still contains a file that labels its Dilithium implementation as simplified/demo. Randomly generated byte arrays are not ML-DSA key material and must never be presented as post-quantum security.

## Required before Mainnet

1. Select a vetted, maintained implementation of NIST-standardized ML-DSA and ML-KEM.
2. Pin dependency versions and record checksums in the build/release process.
3. Replace demo algorithms behind a versioned CryptoSuite interface.
4. Add ML-DSA transaction signing and verification tests.
5. Add ML-KEM P2P key-establishment tests.
6. Add official known-answer/test-vector coverage where available.
7. Add malformed-input, replay, downgrade, and cross-algorithm rejection tests.
8. Fuzz cryptographic serialization/parsing and P2P handshake state machines.
9. Ensure secret keys never enter logs, metrics, traces, or error strings.
10. Benchmark mobile clients, validators, and P2P bandwidth before freezing consensus parameters.
11. Perform independent cryptographic/security review.
12. Freeze the selected cryptographic suite in the Mainnet genesis/protocol specification.

## Release rule

Until all items above have evidence, NexaStream must remain a testnet/release-candidate and must not claim production Mainnet security.
