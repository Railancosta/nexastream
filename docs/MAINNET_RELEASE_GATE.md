# NexaStream Mainnet Release Gate

This document defines the evidence required before NexaStream may be announced as a production mainnet.

## P0 — Network
- [ ] Genesis hash generated and independently reproducible
- [ ] Chain ID fixed and documented
- [ ] Node binary builds from a clean checkout
- [ ] Nodes produce blocks on a clean local network
- [ ] Two or more independent nodes synchronize
- [ ] Fork-choice behavior tested
- [ ] Finality behavior tested
- [ ] Restart/recovery tested
- [ ] Network partition/churn tested

## P0 — Transactions and NST
- [ ] Native wallet generates keys safely
- [ ] Transaction signing and verification tested
- [ ] Real transactions included in blocks
- [ ] Maximum NST supply is enforced at consensus level
- [ ] No production faucet or mock balances
- [ ] Explorer reads chain state rather than fixtures
- [ ] RPC returns live chain data

## P0 — Video/P2P
- [ ] Content receives deterministic content identifiers
- [ ] At least two independent storage peers replicate content
- [ ] Peer discovery works without a centralized database
- [ ] Video can be retrieved from a peer
- [ ] Playback failure/retry behavior tested
- [ ] Node churn does not corrupt content

## P0 — Revenue 50/50
For every eligible revenue event:

`net_distributable_revenue = creator_share + platform_share`

with:

`creator_share = net_distributable_revenue * 0.50`

`platform_share = net_distributable_revenue * 0.50`

Required tests:

| Net revenue | Creator | Platform |
|---:|---:|---:|
| 0 | 0 | 0 |
| 100 | 50 | 50 |
| 1,000 | 500 | 500 |
| 1,000,000 | 500,000 | 500,000 |

No simulated revenue, fake balances, or guaranteed creator income may be presented as real production revenue.

## P0 — Security
- [ ] Clean dependency installation
- [ ] SAST passes
- [ ] Dependency audit reviewed
- [ ] Secrets scan passes
- [ ] Authentication/authorization tests pass
- [ ] Rate-limit tests pass
- [ ] Input validation tests pass
- [ ] Fuzz/property tests for consensus and transaction parsing
- [ ] Critical/high vulnerabilities resolved or formally accepted

## P0 — Production
- [ ] `nexastream.org` points to the intended production frontend
- [ ] API production endpoint verified
- [ ] TLS/HTTPS verified
- [ ] Health checks verified
- [ ] Monitoring and alerting verified
- [ ] Backup and recovery procedure tested
- [ ] Rollback procedure tested
- [ ] Mobile layouts tested at small and large viewport sizes
- [ ] No fake metrics or placeholder production claims

## Internationalization
The application should support arbitrary BCP-47 locales through a centralized translation layer. Portuguese-Brazilian is the fallback locale. Automatic translations generated by local AI may be proposed, but must not silently replace verified product/legal text.

## Release rule
A release may be called **Mainnet Live** only when all P0 items have evidence attached to the release/PR. Creating routes, UI labels, mock data, or documentation does not satisfy a runtime requirement.
